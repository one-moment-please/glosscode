Menus, not a ribbon

A classic menu bar plus one slim toolbar keeps the most vertical space for code. A ribbon suits apps with hundreds of formatting commands, and this app has about forty. Every command lives in a menu with its shortcut shown, and the toolbar holds only the ones you use every few minutes.

Sort words

Program › Sort words puts every line in one fixed order: N, setup G-codes, motion, X, Y, Z, I/J/K/R, F, S, T/H/D, M, others, then the comment. On Fanuc-style controls the order of words in a line doesn't change what it does, so sorting is safe there. Each sort can be undone in one step.

Columns by word type

This layout gives each word type its own column, so X values are always under X and M-codes always sit together. Only the columns a file actually uses appear. Rare words go in an Other column near the end, so there are no rows of empty columns. Click an empty cell to add a word of that type in the right place.

Simulation and preview

▶ plays the program one move at a time. The editor follows along, and the tool marker shows where the cutter is. When you're not playing, moves after the selected line are greyed out, or hidden if you choose that in View. View › Toolpath colors › By tool gives each tool its own color, like the spot drill (T2) here.

Subprograms shown inline

A call like N100 M97 P1000 gets a ▸ show N1000 button. It inserts the subprogram's lines below the call, with a purple bar, a ↳ in the margin and purple N numbers. Editing those rows edits the subprogram itself.

Standard file dialogs

Open and Save call the real system dialog from C: IFileOpenDialog on Windows, and the GTK or desktop-portal dialog on Linux. The nativefiledialog-extended library wraps both behind one call.
